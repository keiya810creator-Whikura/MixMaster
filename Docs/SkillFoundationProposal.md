# 共通スキル基盤・CSV設計案

これは次の実装に向けた設計案です。スキル実行処理・スキルCSVインポーターはまだ追加していません。
`SkillCsvExamples/` の4つのCSVも仕様確認用で、現在の一括インポートには入りません。

## 現状と基本方針

- `SkillSO` にID・名前・習得コスト・必要Lv・Active/Passive・威力参照・対象・MP・倍率・属性がある。
- `MonsterSO.availableSkills` とモンスターCSVの `SkillIds` は既存。複数IDは `;` 区切り。
- モンスターCSVは未登録スキルIDに仮のSkillSOを作る。新インポーターでは同じIDのアセットを更新し、GUIDを維持する。
- 主人公は転生先の `availableSkills` を参照できるが、習得・発動・トリガー・プレイヤーの習得一覧保存は未実装。

「同じスキルID＝同じ効果・射程・MP・クールダウン」とする。違うのは使用者の能力値と敵味方の所属、発動要求の入口だけ。
敵から見たEnemyは主人公・仲間、主人公/仲間から見たEnemyは敵モンスター。Allyには自分も含める。
スキル専用倍率を敵だけに掛ける処理は作らず、必要なら既存の敵/ボス能力補正へまとめる。

## 実行の構成案

1. 使用者を共通の `ISkillActor` で扱う。主人公・仲間・敵のアダプターがHP/MP/能力値/所属/生死/位置/ダメージ・回復処理を提供する。敵にもMPの現在値を用意する。
2. ボタン、トリガー評価、敵AIは `SkillRunner.TryCast(skillId, target)` に要求する。
3. Runnerが習得/装備、MP、生死、対象、射程、クールダウン、詠唱・行動制限を共通判定する。
4. 確定後、共通のEffectExecutorが弾・範囲攻撃・回復等を実行する。既存のダメージ計算、属性耐性、クリティカル、命中演出、討伐報酬の経路へ接続する。

使用者ごと・スキルIDごとにCDを保持し、ボタンとトリガーは同じCDを共有する。通常攻撃速度/移動速度の2倍補正をスキルCDに流用しない。
発動失敗ではMPもCDも消費しない。詠唱完了時に再検証し、成功した瞬間にMP消費とCD開始を確定する。
詠唱中に死亡、射程外、対象消滅ならキャンセルして消費なし。発射後に対象が死亡して弾が外れた場合は返金しない。
同一フレームの複数要求で二重消費しない。詠唱中の重複要求は拒否。共有の発動間隔は初期案0.2秒、CSVでスキルごとに指定する。
ポーズ中はCD/詠唱を停止し、オフライン中は発動しない。再起動時のCDは通常CDから再開し、再起動連打を防ぐ案。

## トリガー案

発動の「きっかけ（イベント）」と「その時に必要な条件」を組み合わせる。閾値を毎フレーム連打する方式は避ける。

| 表示例 | イベントID | 追加条件例 |
| --- | --- | --- |
| 使用可能になったら | Ready | 対象が射程内 |
| 自分のHPが50%以下 | Ready | SelfHpPercent <= 50 |
| 自分のMPが30%以上 | Ready | SelfMpPercent >= 30 |
| 対象のHPが20%以下 | Ready | TargetHpPercent <= 20 |
| 味方のHPが50%以下 | Ready | 対象をLowestHpAllyにしてTargetHpPercent <= 50 |
| 近くに敵が3体以上 | Ready | EnemyCount >= 3（半径指定） |
| 対象との距離が2以下 | Ready | TargetDistance <= 2 |
| 通常攻撃が5回命中したら | NormalAttackHit | イベント回数5 |
| クリティカルを出したら | CriticalHit | 発動確率指定可 |
| ダメージを受けたら | DamageTaken | 自分のHP条件も追加可 |
| 敵を倒したら | EnemyKilled | 有効な討伐イベントのみ |
| 味方が倒れたら | AllyDied | 生存中の自分が使用 |
| 戦闘開始時 | CombatStarted | 戦闘ごとに1回 |
| 10秒ごと | Interval | 間隔10秒 |

初期実装はReady、HP/MP条件、敵数、通常攻撃命中、被ダメージ、Intervalから始め、他のイベントを後で追加してもCSV構成は変えない。
Readyは発動可能になった時/条件変化時と0.2秒の補助チェックで評価し、HP条件が続けばCD後に再使用する。
HPが下がった瞬間に一度だけ使う仕様が必要になった時は、別イベントとして追加する。
敵数は中心を使用者に固定し、半径内の生存した敵を数える。距離はワールド単位。

複数条件は同じルールIDに複数行でAND、ORは別ルールIDで表現する。例：「HP50%以下、かつ敵3体以上」。
複数ルールが同時成立したら優先度が大きい順、同値はルールIDの昇順。同じスキルへの要求は1回にまとめる。
優先度が高い要求がMP不足/射程外なら次の要求を試す。各要求の対象を確定してから条件を調べる。
イベント回数はルールごとに保持。通常攻撃1回が複数敵へ当たっても攻撃IDで重複排除して1回、空振りは0回。
回数到達後は新規イベント時だけ試し、失敗時は到達状態を維持、成功時にリセットする。CD明けの即時発動も欲しい場合はReadyルールを別に追加する。
Intervalは戦闘中の時間だけ数え、発動失敗時も次の間隔へ進める。停止/復帰で未処理分を連発しない。
スキル由来の命中/クリティカル/討伐/被ダメージは記録するが、初期仕様では新たなトリガーを発生させない。発動連鎖による無限ループを防ぐ。

## CSVは4つに分ける

数値は小数点`.`、確率・HP/MP閾値は0～100の数値（`%`は書かない）、時間は秒。IDは変更しない英数字。
表示名は日本語可。列名は以下の日本語、識別用の列値は英語enumで統一。UTF-8 BOMあり/なし、引用符付きセルに対応する。
空欄は列別の既定値を使い、ID・列挙値・必須参照の誤りを暗黙の0に変換しない。

### 1. スキル.csv：1スキル1行

| 列 | 値・意味 |
| --- | --- |
| ID / 名前 / 説明 | 既存skillId / displayName / description |
| 種別 | Active / Passive。初期実装はActiveのみ、Passiveは明示エラー |
| 必要Lv / 習得SP | 既存requiredLevel / skillPointCost。敵の装備は習得SP不要 |
| 消費MP / CT秒 / 詠唱秒 / 発動間隔秒 | MP、通常CD、詠唱、共有の行動制限時間 |
| 射程 / 対象 | 起点から選択対象への許容距離、Self / SingleEnemy / AreaAroundSelf / AreaAroundTarget / SingleAlly |
| 属性 | Owner / None / Fire / Water / Wind / Lightning / Light / Dark。Ownerは既存useOwnerElement=true |
| クリティカル可 | true / false。ダメージのみ。回復は初期仕様ではクリティカルなし |
| アイコンパス | 任意。Assets/以下のSpriteパス。空欄は更新時に既存画像を維持、新規時は未設定 |

Self/AreaAroundSelfは使用者を起点とし射程0。AreaAroundTargetは対象の位置を起点にする。
範囲の半径は効果CSVで指定。SingleAllyは既存enum末尾に追加し、既存シリアライズ値を維持する。
MP回復/蘇生/状態異常/持続ダメージ/パッシブ/バフ重複規則は、この最初の実装の後に追加する。

### 2. スキル効果.csv：1効果1行

| 列 | 値・意味 |
| --- | --- |
| スキルID / 順番 | 参照IDと効果の実行順。組み合わせは一意 |
| 効果 / 威力参照 | Damage / Heal、Attack / Magic / MaxHp / None |
| 倍率 / 固定値 | 参照能力×倍率＋固定値。long上限を超えない飽和計算、負値不可 |
| 適用先 | SelectedTarget / EnemiesInArea / AlliesInArea / Self |
| 配送 | Instant / Projectile。弾命中時も同じ効果を実行 |
| 半径 / 命中上限 | 範囲半径。上限0は制限なし。選択対象/自分は上限1 |
| 弾速 / 弾寿命秒 / 追尾 | Projectile用。Instantでは0/0/false |
| 演出プレファブパス | 任意。Assets/以下のPrefab。空欄は更新時に既存指定を維持 |

Damageは倍率計算した攻撃/魔力を共通DamageCalculatorへ渡し、防御・魔防・属性耐性・クリティカルを既存の戦闘ルールに従って適用する。
Healは倍率＋固定値を直接回復し、防御で軽減しない。敵のHealも敵自身/敵側の味方が対象で、主人公を回復しない。
初期実装ではDamageの威力参照はAttack/Magic、HealはMagic/MaxHp/Noneを許可し、不適切な組み合わせをエラーにする。
順番は同時刻の実行順であり、前の弾の着弾を待つ意味ではない。連続斬りなど時間差効果は後で遅延列を追加する。
範囲は実行時/着弾時に生存者を取り直し、使用者に近い順（同距離は個体ID順）で上限まで選ぶ。
同じ効果は1体に1回。複数Colliderで多重命中しない。射程内の選択対象は敵味方と生死を再検証する。
弾が対象を失った場合は消滅、発射後の別対象への自動変更はしない。
既存SkillSOのpowerSource/powerMultiplierは旧データ移行用に維持し、新ランタイムで効果CSVと二重適用しない。

### 3. スキルトリガー.csv：初期設定/プリセット

| 列 | 値・意味 |
| --- | --- |
| ルールID / スキルID | 識別IDと発動するスキル。同じルールIDの行は同じメタデータを持つ |
| イベント / イベント回数 / 間隔秒 | 上記イベント。回数は通常1、Intervalだけ間隔>0 |
| 条件 / 比較 / 閾値 / 判定半径 | None、SelfHpPercent、SelfMpPercent、TargetHpPercent、EnemyCount、TargetDistance。比較はLE/GE/EQ |
| 対象選択 | Self / CurrentEnemy / NearestEnemy / LowestHpAlly / EventEnemy |
| 発動確率 / 優先度 | 0～100、一度の発動要求で1回だけ抽選。優先度は大きい順 |

Noneは閾値等を空欄。LE=以下、GE=以上、EQ=等しい。割合や距離にEQを使わずLE/GEを推奨。
CurrentEnemy/EventEnemyが無効な場合は失敗、NearestEnemyへの暗黙の置き換えなし。
NearestEnemy/LowestHpAllyはスキル射程内から選ぶ。LowestHpAllyはHP割合が低い順、同率は距離・個体ID順。
同一ルール複数行のイベント/スキル/回数/間隔/対象/確率/優先度が異なる場合はエラー。
対象種別と効果・トリガーの組み合わせも検証（SingleAllyにNearestEnemy等は不可）。

このCSVは選択肢/初期設定であり、仲間全個体の現在設定を表すものではない。
プレイヤー/仲間のUIは任意の条件とAND行を編集でき、その設定はセーブへ保存する。
主人公と仲間は習得・装備したスキルだけを選択可能。個体の設定はMonsterSOに書き込まず、所持個体IDに紐づける。
主人公はボタン＋トリガー、仲間はトリガー。無効な習得ID/削除済みIDは安全に無効化して通知する。

### 4. 敵スキル.csv：敵の装備スキルと自動使用

| 列 | 値・意味 |
| --- | --- |
| モンスターID / スキルID | 既存モンスターIDとスキルID。組み合わせは一意 |
| 初回待機秒 | 出現後に最初の発動を試みるまでの秒数。通常CDを変える列ではない |
| 対象選択 / 優先度 | Self / CurrentEnemy / NearestEnemy / LowestHpAlly、大きい順 |

この表へ載せた敵だけに付与する。通常のモンスターCSVのSkillIdsは「習得可能一覧」、敵スキルCSVは「敵として装備済みの一覧」。
ボスも同じRunnerを使い、初回待機後、共通CTが明けて条件が揃ったら自動発動する。
対象不在/射程外/MP不足なら消費せず待機、初期仕様ではスキルのための追跡AIは追加しない。
敵にもHP条件等を追加したくなった時は任意のルールID列を追加できる。通常のCD自動発動に必須ではない。
例のモンスターID「1」は説明用であり、実際にボスとして使うIDに差し替える。

## インポーターの取り扱い

全CSVを読み、参照を解決・検証してから反映する。重複ID、未知のenum、未知のモンスター/スキル、負数、NaN/Infinity、範囲外割合、効果がないActive、必要なPrefabの不正参照を行番号付きでエラーにする。
更新時は既存アセットをその場で更新してGUIDを維持。CSVから消えた行を無断でアセット削除しない。
効果行/敵の装備一覧は対象ID単位で置換し、再取り込みで追加が累積しないようにする。空CSVで一括削除はせず、削除は別操作とする。
先にスキル本体を検証・更新 → 既存のモンスターCSVでSkillIdsを解決 → 効果/プリセット/敵スキルの参照を確定する2段階方式が必要。
既存の自動生成された仮SkillSOを実装済みと扱わない。効果が未定義なら警告し、使用できない状態にする。
将来の一括取り込みへの登録時にこの順序へ変更する。
