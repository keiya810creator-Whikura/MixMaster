- 「検討中・未確定」：決定済みの仕様として実装しない。

## 2. 装備強化・レアリティ

### 会話の仕様・依頼

- 鍛冶屋への接触で強化できる。通常インベントリでは強化操作を非アクティブにする。
- 費用はゴールドと、そのマップの素材6種。
- MAP1の初回ゴールド費用は6。次回以降は前回費用の1.2倍を切り上げる。
- 各素材の必要数はゴールド費用の1/6。端数処理は現在の実装と会話の記録を照合する。
- 強化は取得時の装備Lvに最大+50できる。
- 能力値は「基礎値 × 強化後の装備Lv」。強化回数だけを基礎値へ掛ける計算にしない。
- 長押しで連続強化できる。
- 装備名に `+1` などの強化回数を表示し、装備Lv表示との整合を保つ。
- エピックは赤、レジェンダリーは従来のエピック相当の紫、Lv150のゴッドは従来のレジェンダリー相当の金。
- レアリティの絞り込みにゴッドを追加する。

### 過去の実装報告

2026年10月18日の報告には、初回費用をボスEnemy IDから算出し、以降1.2倍切り上げ、素材6種は各ゴールド費用/6切り上げ、+50上限・長押し・保存に対応したとの記述がある。MAP1初回6という指定と、現在のマップデータで整合を確認する。Unity全体のコンパイル・画面・実機確認が完了した証拠としては扱わない。

## 3. 仲間・配合・転生

### 会話の仕様・依頼

- 通常配合で進化できる範囲は、親2体のうち高い方の出現Stage+1まで。
- 配合時は親のスキルポイントの合計を引き継ぐ。
- 転生の祭壇では、初期から「人間の書」を所持する。
- 各モンスターの信頼度が5に達すると対応する書が解放され、解放通知を表示する。
- 書を選んで転生し、基礎値の成長やスキル利用につなげる。
- 転生時もスキルポイントを引き継ぐ。
- 書の一覧にソート・お気に入り・フィルターを用意する。
- 起動時のリスポーン位置は村中央。

### 実装状況の確認が必要な点

- 過去の報告には、出現Stage、通常/特殊配合、称号/個体値の継承、配合UIの実装への言及がある。最新コードへの反映を調べる。
- 転生先のスキル使用は当時未実装として相談されている。その後の実装有無を調べる。
- スキルポイントが「総獲得」「未使用」「割当済み」をどう保持するかは、現行のセーブと処理を確認して継承時の二重加算を防ぐ。

## 4. 戦闘・追従・ステータス

### 会話の仕様・依頼

- 近接攻撃は、攻撃範囲に合わせて剣スプライトを調整し、振り回す。前進の挙動は当時の仕様を維持する。
- 遠隔攻撃は当時の仕様を維持する。最新コードを先に確認する。
- 仲間の攻撃範囲を表示する。
- 主人公の自動攻撃トグルを設ける。
- 仲間の低速追従時の震えを解消する。
- ダメージパーティクルの色をダメージ表示と合わせる。
- ダメージテキストは残HPで打ち切らず、残HPを超えたダメージも表示する。
- ステータス表示に速度・範囲などを追加する。
- 攻撃速度と攻撃頻度は別に扱い、相談中の2倍補正をそのまま適用しない。

| 戦闘モードの呼称 | 会話で指定された挙動 |
| --- | --- |
| プレイヤー範囲内攻撃 | プレイヤーの範囲を基準に攻撃 |
| 敵対対象へ接近攻撃 | 敵対対象へ近づいて攻撃 |
| 自動狩り | 全体を索敵し、攻撃範囲に入ったら即攻撃 |
| 自身範囲内攻撃 | 追従中も、自身の攻撃範囲内なら即攻撃 |

攻撃頻度の廃止は検討事項として扱い、確定した変更と判断しない。モードの正式な列挙名・索敵対象・追従優先度はコードで確認する。

## 5. オフライン報酬・記録・UI

### 会話の仕様・依頼

- 記録モードは3分間計測し、1分当たりの取得数へ換算する。
- 復帰時の報酬は「放置時間（分） × 記録した1分当たり取得数 / 2」。端数処理・上限・時間の扱いは現行コードを確認する。
- 記録の上書き時は確認画面を表示する。
- 報酬・記録UIに素材のスプライトを表示する。
- 復帰時に記録画面を自動で開かない。
- 挑戦・リザルト・記録・受取等のUIと、ゴールド表示をPrefab化する依頼がある。
- 帰還ボタンを削除する依頼がある。適用対象の画面は既存コードと最新指示で確認する。
- iPhoneのノッチ領域を含む全画面表示に対応する依頼がある。

## 6. 祭壇・マップ・ダンジョン

- 祭壇の仲間回復は3分クールダウン。
- 死亡した仲間は、指定円内に5秒いることでHP30%で蘇生する。
- 上記祭壇処理はスクリプトのみで対応する依頼がある。
- 村マップの制作では31×31、空き地3×3という指定がある。地形名・配置JSONの形式は実際のアセットで確認する。
- 過去の報告にはマップCSVインポーター、道路生成、ダンジョン自動生成への言及がある。現行のパラメーターと取り込み状況を調べる。
- 素材制作ではモンスター6体それぞれの素材1個と、地域に合わせたダンジョン固有素材1個の計7個を作る運用がある。インポーターへの登録方法は現行データを確認する。

## 7. 直近の変更依頼と、次の開発対象

### モンスタードロップ率

モンスタードロップ率は、ステータスの「ドロップ率」の影響を受けないようにする。

装備・素材・ゴールド等のドロップまで一緒に変更しない。モンスタードロップが指す実際の処理を調べ、変更が既に反映されているか確認する。

### 全キャラクター共通のスキル基盤

| 対象 | ユーザーが指定した発動方法 |
| --- | --- |
| プレイヤー | ボタンでの手動発動と、設定したトリガー条件を満たした際の自動発動 |
| 仲間モンスター | 設定したトリガー条件を満たした際の自動発動 |
| 敵モンスター | ボス等にスキルを設定し、クールダウン後に自動発動 |
| 共通要件 | プレイヤー・仲間・敵が同じスキルを使い、同じ挙動になる |

発動方法が違っても、スキル効果の実行処理は共通にする方針。

直前の相談は「トリガーの種類と、インポーター用CSVをどう設計するか」。具体的なトリガー一覧、CSVの列、効果の型、ターゲット指定、消費リソース、成長式、AND/OR条件、装備/解放方法はまだ確定したものとして扱わない。

### 推奨する開始手順

1. 現在の戦闘・ステータス・スキル・保存・CSV取り込み処理を調べる。
2. 既存処理と、上記の共通スキル要件を対応付ける。
3. トリガー候補とCSV案を、列の意味・型・例を添えて提示する。
4. 確定した範囲を実装し、プレイヤー・仲間・敵で同じ効果処理を使うことを確認する。
