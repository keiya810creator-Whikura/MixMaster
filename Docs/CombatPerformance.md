# 同時討伐時の計算・ドロップ処理の見直し

2026年10月27日

## 変更した処理

### ステータスとパッシブ

従来の `SkillActor.Effective` は、能力値を読むたびに `SkillPassiveRules.Apply` を呼んでいた。1回の能力値参照で、パッシブの種類ごとにスロット・習得状況を再走査し、HashSetとCharacterStats/耐性のコピーを作っていた。コピーを先に作るため、その後の参照比較によるキャッシュも味方では働いていなかった。

- パッシブは個体ごとに、全種類の合計と近接/遠隔切替をまとめて集計する。同一フレーム内の再参照では再走査しない。
- ステータスは同一フレーム・同一時刻・同一入力・同一スキル設定なら計算結果を再利用する。
- スロット変更・習得・リセット・復元はRevisionで失効させる。バフ追加/更新/解除も失効させる。基礎能力値や耐性が同じオブジェクト内で変更された場合も値の比較で検出する。
- 能力値に作用するパッシブも状態異常もなければ、基礎値をそのまま読む。
- 状態異常の有無判定でラムダを作らず、周期処理の一時リストと優先順位順のリストも再利用する。
- スキルID検索・所持個体ID検索を辞書へ変更。追加・売却・配合・復元で個体の索引を同期する。セーブ形式は変更しない。

### ドロップと取得表示

- 素材・モンスタードロップを取得後に非表示のプールへ戻す。次の出現時に位置、経過時間、速度、素材、数量、討伐者、IV、称号を初期化する。
- `DropManager` は各32個を複数フレームに分けて事前準備する。保持上限は各128個。Inspectorの `Prewarm Per Type` / `Retained Per Type` で変更できる。
- 上限は取得済みで非表示のオブジェクトに対するもの。出現中のアイテムを減らしたり、報酬をまとめたりしない。プールが空なら従来どおり追加生成する。シーン破棄で失効したプール要素は取得時に飛ばす。
- 仲間取得ログも最大表示行数のTMPを再利用する。表示内容、色、順序、表示時間は維持する。
- ドロップの詳細IV Consoleログは既定で無効。必要な場合はMonsterDropPickupの `Log Individual Values` を有効にする。画面上の仲間取得ログは引き続き表示する。
- 討伐経験値に伴う仲間HUDの再描画は、同一フレーム内でまとめる。報酬・経験値・レベル/信頼度イベント自体は遅延・合算しない。
- 死亡時に使うPlayerManager/MonsterManager参照も共有する。

既存Prefab、素材、スキルExcelの再生成・再取り込みは不要。

## 確認結果

Unityそのものではなく、Unity APIの代替アダプターを使った.NET上の比較・結合検証。

| 確認 | 結果 |
| --- | --- |
| ウォームアップ後、同一フレーム/同一入力の能力値2万回参照 | 結果一致。変更前は約132.48 MBの一時確保と2万回の能力値コピー。変更後は測定区間の追加確保・コピーとも0 |
| 入力・耐性の変更、装備スキル変更、重ね掛け、期限切れ | 基礎計算との一致、同フレーム中の失効を確認 |
| 実SkillActor/SkillProgressionManager/MonsterManagerの結合 | 習得・設定・詠唱・MP不足・優先順位・DoTによる睡眠解除・セーブ復元を確認 |
| 事前準備後、素材1000個とモンスター200体を順次出現/取得 | 追加Prefab生成0。数量、討伐元、IV、称号の維持と二重取得の防止を確認 |
| 同時にプール数を超える出現、破棄済みプール要素、保持上限 | 追加生成・再検索・上限処理を確認 |
| 所持個体の辞書 | 取得、経験値、単体/一括売却、自動売却、配合、復元後の追加/削除を確認 |
| 仲間取得1000回 | 表示用テキスト4個を再利用 |
| 経験値通知300回 | HUD更新を1回に集約 |

計算比較498項目、実スキル結合122項目、取得/索引1220項目、UI集中更新12項目が成功。C#はPlayer/Editor両設定で構文エラーなし。これらはUnity Editor全体コンパイルや実機FPSの証明ではない。

## Unityで確認する箇所

同じマップ・同じ敵数・同じ範囲スキルで比較する。CPU ProfilerのTimelineとGC Allocを、攻撃時・死亡時・吸収時に分けて確認する。HP/MP、パッシブの付け替え、バフ更新、ドロップ数量/討伐者色、個体値/称号を併せて確認する。

初回プールを超える大量出現では追加生成が残る。敵自体の生成/破棄、Physics、描画、30秒ごとのJSON保存等の負荷は別に残る。Unity EditorのPlay Mode、モバイル実機、Profilerによるフレーム時間はこの環境では未確認。
