# 装備強化

鍛冶屋に触れると、強化ボタンが有効な装備インベントリが開きます。
装備を選び、「強化」を押すと強化画面が開きます。
通常メニュー・仲間の装備変更から開いたインベントリでは強化ボタンを非表示にします。
鍛冶屋のインベントリを閉じると、強化の許可と移動・ジョイスティックのロックを解除します。
タップで1回、長押しで連続購入します。指を離す、ボタン外へ移動する、
画面を閉じる、費用が不足する、＋50に達する、のいずれかで停止します。

## レベルと能力値

- 取得時のLvに最大50を加算します。Lv20なら70まで、Lv100なら150までです。
- `EquipmentRecord.originalLevel` が取得時Lv、`enhancementCount` が購入済み回数です。
- 既存の `level` は取得時Lv＋強化回数を保持します。
- 能力値・耐性・ドロップ率は従来の「基礎補正×装備Lv」で計算します。
- 主人公・仲間が装備中でも強化でき、既存の装備変更イベントで能力値を更新します。
- ドロップ時のLv範囲は従来通り1～100です。
- 旧セーブの装備Lvを取得時Lvとして引き継ぎ、強化済みLv150も保存・復元できます。
- 装備一覧・選択詳細の名前は「草原の獣牙剣 Lv101 《レジェンダリーレア》 +1」の形式です。未強化は+0を表示します。
- エピックレア（Lv86～95）は赤系、レジェンダリーレア（Lv96～149）は従来のエピックと同じ紫、ゴッドレア（Lv150）は従来のレジェンダリーと同じ金色です。
- レア度絞り込みにもゴッドレアを追加し、Lv150の装備を抽出できます。

## 費用

初回Goldは装備の出身マップのボスEnemy IDの数値部分です。
例：`MON_006` は6G。2回目からは直前のGold×1.2を毎回切り上げます。
そのマップにいる全モンスターの素材6種を、それぞれGold÷6の切り上げ個数消費します。
ダンジョン固有素材は消費しません。

MAP1のGoldは6、8、10、12、15、18、22、27、33、40…と増えます。
50回目は61,212G、50回の累計は367,152G、各素材の累計は61,207個です。

現在の討伐報酬コードは「ID数値×敵Lv、称号付きはさらに2倍」です。
今回の強化費用は指定例の6Gに合わせ、ボスID数値を基準とします。

全費用を確認してからGold・素材・Lvをまとめて更新し、その後に通知します。
いずれか1種類でも不足すると、他の素材やGoldも消費しません。
連続購入中の保存は既存の `HoldToUpgradeButton` により購入操作の終了時に行います。
既存のアプリ一時停止・終了時の自動保存も利用します。

## マップ設定

配置済みの鍛冶屋をHierarchyで選択し、
「MixMaster > Map > 選択した鍛冶屋にアクセスTriggerを追加」を一度実行してシーンを保存します。
入口前に接触Triggerを作り、既存の装備インベントリと建物UIルーターを接続します。
建物の固いColliderは保持します。Tilemap上の建物は入口前に空のGameObjectを置き、
そのオブジェクトを選んで同じメニューを実行してください。
手動で設定する場合は、入口Triggerの `MapBuildingAccess.BuildingType` を `Blacksmith` にし、
ルーターの `Blacksmith Inventory` にシーン内の装備インベントリを割り当てます。
未指定の場合もシーン内の非アクティブなインベントリを検索して再利用します。

取得した装備に `sourceMapId` を保存するため、プレイヤーの現在地が変わっても
費用・素材は出身マップを参照します。旧装備は `MapSO.dungeonEquipment` から
出身を特定します。初期装備 `EQP_001` / `EQP_002` は `MAP_001` を使います。
旧装備に複数の出身候補がある場合は、費用を決めず設定エラーを表示します。

`Assets/Resources/Data/MapCatalog.asset` を追加しました。
カタログはEditor起動時・マップCSVインポート後・ビルド前に更新します。
手動更新は「MixMaster > Data > マップカタログを更新」です。
各マップにボスと、異なる固有素材を持つモンスター6種を設定してください。
既存の装備インベントリPrefabはそのまま使用できます。

## 検証

「MixMaster > Tests > 装備強化を検証」で、切り上げ・6種それぞれの不足・
Gold不足・通知時の一貫性・再入防止・＋50上限・Lv150の保存復元・旧セーブ・
出身マップの保持を検証できます。NUnitやasmdefの追加は不要です。

今回の検証では、実際のC#ソースをC# 9としてコンパイルし、Unityの基本APIを
代替した実行環境で上記の強化チェックを通過しました。同じ方法で既存の
`HoldToUpgradeButton` のタップ・長押し・解放・不足・範囲外・停止時間・
画面無効化による停止と保存も検証しました。不足で停止してから時間を置いて
指を離した際に追加購入が起きないよう、解放クリックの抑制を補強しています。
Unityエディターでの全体コンパイル・ネイティブUI入力・実機表示は未実施です。

Playモードでは、短いタップ、長押し、指を離す／外へ動かす、素材不足時の停止、
残り1回での停止、画面を閉じて再起動した後のLvと残高を確認してください。
画面表示はスマートフォンの縦画面でも確認してください。
